# XNU syscall table notes

Source of truth: `bsd/kern/syscalls.master` in `apple-oss-distributions/xnu`.
`bsd/sys/syscall.h` is generated by `makesyscalls.sh` during a kernel build and
is **not** committed - a GitHub raw fetch of it 404s on every tag
(11215.41.3, 12377.121.6, and main all checked). Generate from the master.

```bash
curl -sSL -o syscalls.master \
  https://raw.githubusercontent.com/apple-oss-distributions/xnu/xnu-12377.121.6/bsd/kern/syscalls.master
python3 gen_syscalls.py --master syscalls.master --format c > syscalls_gen.h
```

## What the master contains

* **669 entries, 558 unique numbers, max 557** in 12377 (and the same shape in
  11215). Numbers are sparse and stable; unassigned numbers stay unassigned.
* One numbering for ALL architectures. There is no arm64-private space, no
  `-m32` variant. A port never needs a per-arch table.
* The **Files** column (`ALL`, `T`, `N`, `H`, `P`) controls which generated
  artifacts get an entry. Only `H`/`ALL` entries belong in a header.
* `NO_SYSCALL_STUB` means "no libSystem stub is emitted" - the number is still
  valid for `syscall(2)`-style direct use.

## The duplicate-number problem

`557` is both `coalition_policy_get` and `enosys`. `nosys` appears 90 times,
`enosys` 13 times across the file. Two consequences:

1. A C enum generated naively fails: `DNT_SYS_ENOSYS = 8` then `= 11`.
   `gen_syscalls.py` emits one symbol per number (`ENOSYS`, `ENOSYS_11`, ...)
   and keeps aliases as comments.
2. When you implement a number, read BOTH names. The second is usually the
   `#else` of a config guard (`SOCKETS`, `CONFIG_VFORK`, `CONFIG_COALITIONS`,
   `NECP`, `SENDFILE`, `PSYNCH`, `CONFIG_MACF`, `SYSV_{SEM,MSG,SHM}`,
   `CONFIG_EMBEDDED`, `NETWORKING`, `SKYWALK`, `PGO`, ...). If the `#else` is
   `nosys`, the ABI answer is ENOSYS on a kernel built without that feature;
   if it is a real call with a different ABI, you must pick one and document it.

## Reading the master mechanically

```
NUMBER  AUDIT  FILES  { ret name(args) [ATTR] } [comment]
```
* guards are tracked as a stack; `#else` inverts the current condition
* the audit field is irrelevant to a userspace port
* `user_addr_t` / `user_size_t` are guest pointers. On a 64-bit target they are
  u64; on a 32-bit target the kernel zext's them on entry, which a port must
  reproduce or pointer truncation bugs follow.

## Return ABI (arm64)

```
x0 = value or -errno   (errno conventions: 2 = ENOENT AND "read returned 2";
                        never infer failure from x0 alone)
carry flag = 1 on error (syscall(2) glue uses it)
x1 = error secondary value (e.g. 64-bit split returns)
x16 = syscall number on entry
```
`gen_syscalls.py --check N` prints the real prototype and guard for a number,
which is the fastest way to answer "is this syscall Darwin-only".
